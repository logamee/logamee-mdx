# 文档生命周期与用户行为规范

本规范适用于 logamee-mdx（简称 mdx）。

## 状态

- 状态：生效
- 最近审阅：2026-08-14
- 适用对象：实现编辑器、工作区、预览、保存、恢复和导出的开发者与测试者。
- 相关代码：`src/App.tsx`、`src/hooks/useDocumentSession.ts`、
  `src/lib/documentSession.ts`、`src/lib/closeGuard.ts`、`src/lib/crashDrafts.ts`、
  `src/lib/exportPreflight.ts`、`src/lib/htmlPreviewPolicy.ts`、
  `src/lib/pdfRenderScheduler.ts`、`src/lib/docxSanitizer.ts`、
  `src/lib/tauriCommands.ts`, `src-tauri/src/html_preview_server.rs` 及对应 Rust
  命令。

## 用户可观察的主状态

```text
没有文档
   │ 打开意图
   ▼
准备中 ──失败/取消──► 原状态 + 模态对话框
   │ 提交回执
   ▼
已打开/已同步 ──编辑──► 已修改
   │                         │ 保存
   │ 外部变化                  ▼
   └──────────────► 外部变化/冲突对话框
                              │
                              ├─保留本地 / 重新载入 / 另存
                              └─恢复到可判断状态
```

“已修改”只表示内存内容与最近一次确认保存不同；“保存中”表示存在未
完成的工作，不等于已经落盘。任何无法确认的结果都进入显式恢复分支。

## 打开文档

### 支持的入口

- 打开文件/目录对话框；
- `.md`、`.mdx`、`.markdown`、`.mdown`、`.mkd` 文件关联和启动参数；
- 文件管理器拖放；
- 最近文件；
- 上次工作区会话恢复；
- 第二实例或 macOS `Opened` 事件。

所有入口先转为 `OpenIntentCoordinator` 的统一意图。单次启动请求只允许
一个文件或目录；重复目标合并并聚焦已有窗口，非法目标通过模态对话框反馈。
本次启动若带有显式启动参数文件，则该文件优先于上次工作区会话，不再追加会话恢复。

### 打开提交

1. 后端检查候选路径、文件类型、工作区作用域和文件版本，返回准备响应和
   打开回执。
2. 前端创建带 `documentId`/世代编号的 `provisional` 临时状态，并准备编辑器、
   预览和文件监视器。
3. 后端提交成功后，前端将状态标记为 `committed`，更新最近文件、会话和
   原生菜单；提交响应丢失时通过状态查询确认。
4. 任何异步结果若不再匹配当前文档或工作区身份，丢弃结果，不得
   覆盖用户已经打开的新内容。

## 编辑与预览

- Markdown 和 HTML 使用文本编辑表面；Excalidraw 使用其场景编辑器；图片、
  音频、视频、PDF、DOCX 是只读预览。界面不得显示不存在的编辑能力。
- Markdown 预处理必须避开常见围栏代码块，并保持 GFM 表格、数学分隔符、
  引用块硬换行等既有语义；每项规则有 `src/lib/markdown`
  测试。
- 实时预览以 `previewRevision` 和当前文档身份关联，旧渲染、旧媒体插入
  握手或旧独立窗口事件不得回写新文档。
- 重型预览懒加载；加载失败保留面板和返回动作，不清空编辑内容。

## 保存与冲突

### 普通保存

1. 前端先做当前文档、工作区和内容世代编号检查。
2. Rust 端比较预期文件版本，执行持久/原子写入，并返回
   `DocumentSaveResponse`。
3. 只有确认 `committed` 后才更新 `lastSavedContent`、已保存状态、崩溃草稿
   清理和预览关联版本。

### 外部修改/保存冲突

- 文件监视器发现磁盘版本变化时，不自动覆盖未保存内容。
- 无本地编辑时可以重新读取并显示同步结果；有本地编辑时打开冲突对话框，
  提供重新载入、保留本地/另存或取消等明确分支（以当前组件实际提供的
  动作为准）。
- 覆盖令牌只对一次明确的用户确认有效，失败或取消后立即失效。
- 用户关闭、切换文档或退出程序时，若内容未保存，使用显式未保存退出
  对话框；不得使用裸 `window.confirm` 或静默丢弃。

## 工作区生命周期

- 选择目录后生成工作区快照和令牌，文件树和大纲只读取该快照。
- 通过启动参数、文件关联、拖放或第二实例成功打开单文件后，文件树自动切换到该文件的父目录作为工作区根；仅在文件提交成功且父目录工作区授权成功后应用新快照，联动失败不撤销已打开的文件，并显示模态错误。
- 创建 Markdown/Excalidraw/目录、重命名、移动和删除先校验名称/目标/权限，
  成功后使用 `fresh` 回执更新；`stale` 回执触发全量刷新。
- 重命名或移动活动文档/其父目录时，同步更新活动路径；如果无法证明
  新路径，保留旧状态并显示恢复提示。
- 删除走系统回收站；结果为 `indeterminate` 时保留待处理状态和恢复信息，
  不从树中无条件移除。
- 工作区搜索索引有独立世代编号、取消和失效机制；旧查询结果不能在
  切换目录后继续显示。

## 崩溃草稿与恢复

- 编辑中的内容按既有崩溃草稿协议保存到应用数据目录，带文档身份、修订号
  和有界大小；不把草稿写回用户文档路径。
- 启动时列出可恢复草稿，用户明确选择恢复、丢弃或稍后处理；恢复失败
  不删除原草稿，并通过修复/恢复模态对话框给出下一步。
- 成功保存后清理对应草稿；清理失败不影响已保存文档，但要留下可诊断的
  反馈和测试证据。

## 资源插入与导出

- 当前 Markdown 工作区资源插入中，图片生成图片语法，音频只生成普通链接，
  视频不属于可插入资源；音视频文件本身使用独立只读预览。这些能力都不表示
  Markdown 正文已经支持音视频内嵌播放。
- 未来计划在 Markdown 实时预览中支持工作区内视频和音频的正文内嵌与播放。
  实现必须绑定当前文档身份与作用域，生成相对引用或受控资源包，复用授权
  资源读取和过期结果防护，并定义格式兼容、加载失败、无障碍和导出降级；
  不得把临时绝对路径写进 Markdown。在这些契约和回归测试交付前，界面不得
  宣称已支持音视频内嵌。
- HTML 文件通过本地预览服务 + iframe 沙箱预览，不将 HTML 注入宿主 DOM。
  独立预览实际允许脚本、同源、表单、模态窗口、弹窗、弹窗逃逸沙箱和下载；
  Markdown HTML 嵌入只允许脚本、同源和表单。两者都不经过 HTML 净化器。
  DOCX 和富文本粘贴走各自净化器或白名单，离线 HTML 导出也先净化正文。Markdown
  粘贴同时提供 HTML 与纯文本时，若 HTML 仅是无语义容器且文本一致，保留纯文本
  Markdown 源码；实际富文本语义仍按白名单转换，表格单元格和链接等必要转义不变。
  PDF 使用受限的 PDF.js 画布渲染，不走 DOCX/HTML 净化器。资源加载失败保留
  替代文本、文件名或错误说明。
- 打开导出对话框时运行 `collectExportPreflightIssues`。它实际只产生四类问题：
  图片缺失、文档字符数超限、图表渲染错误和大小超限；其中大小超限仅在调用方
  提供相应数据时检查生成 HTML 字节数、图片字节数或 PNG 像素数。具体导出器
  继续执行自己的格式与大小校验；该预检不推断资源授权或通用格式兼容性。
  已有问题时不启动写入。
- 导出写入由 Rust 对话框和持久写入器完成，不能改变当前文档保存状态；
  目标冲突、取消和错误都必须可区分。

## 验收场景

| 场景 | 必须观察到的结果 |
|---|---|
| 启动参数指向有效 Markdown | 主窗口聚焦并打开一次，文件树/编辑器/预览身份一致 |
| 启动参数指向有效 Markdown且存在旧会话 | 只打开启动参数指定的文件，不恢复旧工作区或活动文件 |
| 外部单文件成功打开且存在旧工作区 | 文件树切换到当前文件父目录，编辑器仍显示同一文件；目录联动失败时保留已打开文件并显示模态错误 |
| 重复拖放同一文件 | 请求合并或聚焦，不创建重复文档状态 |
| 打开后外部修改且本地未编辑 | 提示可重新载入，不能悄悄覆盖磁盘新内容 |
| 打开后外部修改且本地已编辑 | 显式冲突分支，保留本地文本直到用户选择 |
| 保存时目标被替换/删除 | 不显示已保存；给出冲突或恢复信息 |
| 删除操作结果无法证明 | 显示不确定结果/恢复信息，不把条目当作已删除 |
| 切换工作区后旧索引返回 | 丢弃旧结果，不污染新文件树/搜索列表 |
| 崩溃草稿存在 | 启动显示恢复对话框，选择后内容可继续编辑 |
| PDF/DOCX 超过限制 | 在读取前拒绝并显示友好错误，不分配无限内存 |
| 导出资源缺失 | 预检阻止写入并列出可行动问题 |

实现或测试无法满足某一场景时，必须在变更说明和 `DESIGN.md`/本规范的
待决问题中记录，不得用“编译通过”代替行为验收。
