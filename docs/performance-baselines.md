# 工作区索引性能基线

本基线适用于 logamee-mdx（简称 mdx）。

本文档记录 `scripts/perf/baselines/` 中提交的 10k/100k 测试夹具基线。它们
是工程验收门槛，不是对用户设备或产品体验的承诺；更换实现、运行器、测试夹具
或测量定义时必须重新生成并解释原因。

## 测量定义

- 每个语料库使用固定的测试夹具版本、随机种子、摘要以及预热/采样/进程计数；
  产物必须通过 `scripts/perf/baseline-schema.mjs` 校验。
- 增量内存峰值使用独立进程的最大驻留集大小（RSS）峰值减去构建前测量值；
  不得把总进程内存或估算索引大小冒充该指标。
- 冷构建、热查询和取消的 p95 只比较 `status: complete`、`errorCount: 0` 且
  可比较的产物。
- 100,000 文件语料库的任何构建、查询、内存或取消变化，都必须说明是否触发
  FTS5 ADR；不能只看单一耗时数字。

## 门禁命令与语义

日常验证使用非破坏性门禁：

```bash
npm run perf:gate
```

候选结果写入 `.perf/`；门禁**绝不会覆盖 `scripts/perf/baselines/`**。
评估结果只有 `pass`、`fail` 或 `not-comparable` 三种语义：

- `pass`：产物完整、可比较，所有适用 p95 门槛通过；
- `fail`：可比较但至少一个门槛失败，必须调查或记录已批准的基线重建；
- `not-comparable`：缺少字段、环境/实现/测试夹具不一致或测量未完成，不得
  当作通过，也不自动当作性能回归。

只有结果完整、可比较且所有适用 p95 门槛均通过时，命令退出码才为 0。
性能基线是工程验收门槛，不是产品体验承诺。

只有在审阅并批准重建基线后，才运行 `npm run perf:baseline:10k` 或
`npm run perf:baseline:100k`。这两个命令会覆盖 `scripts/perf/baselines/` 中的
提交基线，必须连同产物差异、测量环境和变更原因一起评审。
